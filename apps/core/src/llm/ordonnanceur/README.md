# Ordonnanceur LLM (`LLMQueue`)

Réécriture en mémoire de `llm_core/_scheduling` et `_queue.py`, alignée sur le Python 77aac4e et rejouée sur les goldens `ordonnanceur_*.json`. Par serveur, niveau 1 (`_locks.py`) : le modèle tenu accueille toute demande, un changement attend la fin des tours ; un `low` s'arrête au portail devant un `high` inscrit (tant qu'il en reste un) ou devant la grâce de 8 s d'un autre modèle, jusqu'à 30 s après son premier blocage, puis se range derrière les `high` déjà inscrits ; les inscrits sont revus à chaque libération, dans leur ordre d'attente. Niveau 2 (`_concurrency.py`) : une place de modèle, puis un créneau, `high` avant `low`, un `low` qui attend depuis plus de 30 s passant à son rang. Disjoncteur porté de `_breaker.py` ; état du widget ; `stats()` = `get_stats()` du niveau 2.

Boucle :
- un tour = `withLLM(model, priority, signal, fn, { outils: true })` ; chaque appel au moteur passe par `slot.appelLLM(fn)` : en optimized, créneau pris puis rendu autour de l'appel, le modèle restant tenu pendant les outils ; en classic, créneau tenu tout le tour.
- `withLLM` imbriqué sur le même serveur : si le slot du tour tient son créneau (classic, ou compaction lancée pendant un appel), il est réutilisé sans acquisition ; s'il l'a cédé (outils en optimized), c'est une admission d'enfant : son modèle, sa priorité, un créneau par appel, sans tenir de modèle (`llm_slot` du Python).
- boucle enfant (sous-agent) : depuis l'outil, `withLLM(modeleEnfant, prioriteDuParent, signal, (s) => boucle(s), { outils: true })`, chaque appel dans `s.appelLLM` ; jamais le slot du parent.

Disparu : `_shared_slots`, `_locks` Redis, `LLM_GRACE_SOURCE` et partage par worker (un seul process génère) ; `cancel_probe` sondé toutes les 0,25 s (un `AbortSignal` sort sur-le-champ, `on_wait` revient à l'appelant) ; sondes de 1 s du portail (réveils exacts) ; `record_model_load_duration` (sans appelant) ; `python.ts` sera remplacé par `@elpis/commun`.

Routes :
- `process.ts` pose la file unique du process : politique de l'intégré lue dans la configuration (`LLAMA_MAX_MODELS`, `LLAMA_MAX_CONCURRENCY`), celle d'un connecteur relue en base toutes les 5 s (oubliée à sa suppression, `oublierServeur`), `total_slots` de son `/props`, inventaire du routeur, mode, disjoncteur. Les créneaux d'images y passent aussi (serveurs `image:<url>`, politique `politiqueServeurImages` : un modèle, `max_concurrent` du moteur) ; `brancherBoucle` la pose pour la boucle, les sous-agents et les images.
- `avecLLM` (infill, attente bornée à 20 s ; disjoncteur consulté avant toute sonde du serveur) ; `tenirModele` = `MODEL_EXCLUSIVITY.acquire_for` du chargement (`modeleSeul` : niveau 1 seul, sans créneau ni disjoncteur) ; `occupation()` = `snapshot_async()` lu par le déchargement ; `etatFile` = `get_queue_status_for_async` ; `stats()` nourrit `/api/llm/queue-status`.
- `BREAKER_TRANSPORT_ERRORS` (disjoncteur.ts) : la liste `_BREAKER_TRANSPORT_ERRORS` du garde Python (noms httpx), en un seul exemplaire, lue par l'infill ; le garde TS classe ses propres pannes par `classerErreur` (`llmErrorKind` : `unreachable`, `timeout`) ; une panne vue hors du garde passe par le port `PortDisjoncteur` de `process.ts`.
