# LLM scheduler (`LLMQueue`)

In-memory rewrite of `llm_core/_scheduling` and `_queue.py`, aligned with the legacy Python at 77aac4e and replayed against the `ordonnanceur_*.json` goldens. Per server, level 1 (`_locks.py`): the held model accepts any request, a change waits for the turns to finish; a `low` stops at the gate in front of a registered `high` (as long as one remains) or in front of another model's 8 s grace, up to 30 s after its first block, then queues behind the `high` requests already registered; registered requests are re-examined at each release, in their waiting order. Level 2 (`_concurrency.py`): a model place, then a slot, `high` before `low`, a `low` that has waited more than 30 s moving up to its turn. Circuit breaker ported from `_breaker.py`; widget state; `stats()` = level 2's `get_stats()`.

Loop:
- a turn = `withLLM(model, priority, signal, fn, { outils: true })`; each call to the engine goes through `slot.appelLLM(fn)`: in optimized mode, the slot is taken then released around the call, the model staying held during the tools; in classic mode, the slot is held for the whole turn.
- nested `withLLM` on the same server: if the turn's slot holds its slot (classic, or compaction started during a call), it is reused without acquisition; if it gave it up (tools in optimized mode), it is a child admission: its model, its priority, one slot per call, without holding a model (Python's `llm_slot`).
- child loop (subagent): from the tool, `withLLM(modeleEnfant, prioriteDuParent, signal, (s) => boucle(s), { outils: true })`, each call in `s.appelLLM`; never the parent's slot.

Gone: `_shared_slots`, Redis `_locks`, `LLM_GRACE_SOURCE` and per-worker sharing (a single process generates); `cancel_probe` polled every 0.25 s (an `AbortSignal` exits immediately, `on_wait` returns to the caller); the gate's 1 s probes (exact wake-ups); `record_model_load_duration` (no caller); `python.ts` will be replaced by `@elpis/commun`.

Routes:
- `process.ts` sets up the process's single queue: the built-in engine's policy read from the configuration (`LLAMA_MAX_MODELS`, `LLAMA_MAX_CONCURRENCY`), a connector's policy re-read from the database every 5 s (forgotten when it is deleted, `oublierServeur`), `total_slots` from its `/props`, router inventory, mode, circuit breaker. Image slots go through it too (`image:<url>` servers, `politiqueServeurImages` policy: one model, the engine's `max_concurrent`); `brancherBoucle` sets it up for the loop, subagents and images.
- `avecLLM` (infill, wait bounded to 20 s; breaker consulted before any probe of the server); `tenirModele` = loading's `MODEL_EXCLUSIVITY.acquire_for` (`modeleSeul`: level 1 only, no slot or breaker); `occupation()` = `snapshot_async()` read by unloading; `etatFile` = `get_queue_status_for_async`; `stats()` feeds `/api/llm/queue-status`.
- `BREAKER_TRANSPORT_ERRORS` (disjoncteur.ts): the Python guard's `_BREAKER_TRANSPORT_ERRORS` list (httpx names), in a single copy, read by infill; the TS guard classifies its own failures with `classerErreur` (`llmErrorKind`: `unreachable`, `timeout`); a failure seen outside the guard goes through `process.ts`'s `PortDisjoncteur` port.
